# Developer & Maintenance Guide

This guide contains instructions on how to build, deploy, and publish the Jake Altom Portfolio to GitHub.

## 1. Automated GitHub Pages Deployment (Recommended)

An automated GitHub Actions workflow is set up in `.github/workflows/deploy.yml`.

### Step 1: Push Your Code to GitHub
```bash
git add .
git commit -m "Update portfolio build and deployment"
git push origin main
```

### Step 2: Configure GitHub Pages Settings (One-Time Setup)
1. Go to your repository on GitHub (`https://github.com/jaltom2105/<your-repo-name>`).
2. Click **Settings** at the top.
3. In the left sidebar, click **Pages**.
4. Under **Build and deployment > Source**, choose **GitHub Actions** from the dropdown.
5. GitHub will now automatically build and publish your website whenever you push changes to `main`.

---

## 2. Manual Build & Deployment via gh-pages Branch (Alternative)

If you prefer to build locally and deploy the compiled `dist/` directory to a `gh-pages` branch:

### Step 1: Build the Production Bundle
```bash
npm run build
```
This compiles and bundles all HTML, CSS, JavaScript, and static assets into the `dist/` folder.

### Step 2: Deploy dist to GitHub Pages
You can use `git subtree` to push only the `dist` directory to your `gh-pages` branch:

```bash
git add dist -f
git commit -m "Deploy production build"
git push origin `git subtree split --prefix dist main`:gh-pages --force
```

Then in **Settings > Pages**, set the source to **Deploy from a branch** and select `gh-pages` / `/ (root)`.

---

## 3. Project Structure & Assets

- `public/`: Any static assets placed here (such as `jets.jpg` and `resume_latest.jpg`) are automatically copied into the root of `dist/` during the build.
- `dist/`: The production output generated by `npm run build`.
- `vite.config.ts`: Configured with `base: './'` for seamless hosting on custom domains or GitHub Pages subdirectories.
