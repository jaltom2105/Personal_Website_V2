# Developer & Maintenance Guide

This guide contains instructions on how to build, deploy, and publish the Jake Altom Portfolio to GitHub.

## 1. Automated GitHub Pages Deployment (Recommended)

An automated GitHub Actions workflow is set up in `.github/workflows/deploy.yml`.

### Step 1: Push Your Code to GitHub
```bash
git add .
git commit -m "Update portfolio build and deployment"
git push origin main
```

### Step 2: Configure GitHub Pages Settings (One-Time Setup)
1. Go to your repository on GitHub (`https://github.com/jaltom2105/Personal_Website_V2`).
2. Click **Settings** at the top.
3. In the left sidebar, click **Pages**.
4. Under **Build and deployment > Source**, choose **GitHub Actions** from the dropdown.
5. GitHub will now automatically build and publish your website whenever you push changes to `main`.

---

## 2. Manual Build & Deployment via gh-pages Branch (Alternative)

If you prefer to build locally and deploy the compiled `dist/` directory to a `gh-pages` branch:

### Step 1: Build the Production Bundle
```bash
npm run build
```
This compiles and bundles all HTML, CSS, JavaScript, and static assets into the `dist/` folder.

### Step 2: Deploy dist to GitHub Pages
You can use `git subtree` to push only the `dist` directory to your `gh-pages` branch:

```bash
git add dist -f
git commit -m "Deploy production build"
git push origin `git subtree split --prefix dist main`:gh-pages --force
```

Then in **Settings > Pages**, set the source to **Deploy from a branch** and select `gh-pages` / `/ (root)`.

---

## 3. Project Structure & Assets

- `public/`: Any static assets placed here (such as `.nojekyll`, `jets.jpg`, `resume_latest.jpg`, and `script.js`) are automatically copied into the root of `dist/` during the build.
- `dist/`: The production output generated by `npm run build`.
- `.nojekyll`: Disables Jekyll processing on GitHub Pages so asset directories and static scripts load without interference.
- `vite.config.ts`: Configured to dynamically use `/Personal_Website_V2/` in GitHub Actions and `./` in local/preview environments.

---

## 4. Troubleshooting a Blank Page on GitHub Pages

If you see a blank white page on GitHub Pages, verify the following:

1. **Check Build Status in the Actions Tab**:
   - Go to `https://github.com/jaltom2105/Personal_Website_V2/actions`.
   - Ensure the `Deploy to GitHub Pages` workflow has run with a green checkmark.
   - If it hasn't run yet, you can trigger it manually under **Actions > Deploy to GitHub Pages > Run workflow**.

2. **Verify Pages Source in Repository Settings**:
   - Go to **Settings > Pages**.
   - Under **Build and deployment > Source**, ensure **GitHub Actions** is selected.
   - If your repository is configured to **Deploy from a branch** (`main` / `/ root`), both methods are now fully supported with `.nojekyll` and relative static asset handling.

3. **Hard Refresh / Cache**:
   - After a new deployment finishes, perform a hard refresh in your browser (`Ctrl+F5` or `Cmd+Shift+R`) to clear cached older files.
